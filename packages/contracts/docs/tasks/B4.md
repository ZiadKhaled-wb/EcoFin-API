## Goal
One package that defines every Sprint 1 request and response, the error shape and codes, the roles and the permission keys, so the server and client can't disagree.

## Slice text (F03)
- A shared package (npm package or git submodule, since the repos are separate) with zod schemas and exported TypeScript types

- The standard error shape and the list of error codes
- The shared list of permission keys and roles (used by F06)

## Decisions already made (don't reopen)
- Package name `@ecotech/contracts`, version `0.1.0`, built with `tsc` to `dist/` (ESM + `.d.ts`). Consumers use `"file:../EcoFin-Contracts"` for now; later `github:<owner>/EcoFin-Contracts#v0.1.0`, so add a `prepare` script that runs the build (git deps run `prepare`).
- Both consumers are ESM (`"type": "module"`, TS `moduleResolution: "bundler"`, `verbatimModuleSyntax`). The API also runs the built output under plain Node. So build with `module`/`moduleResolution` `NodeNext` (relative imports end in `.js`), `"type": "module"`, and an `exports` map with `types` + `import`.
- `zod` is a **dependency** pinned to the API's range `^3.25.76`, using the classic `zod` import (not `zod/v4`).
- Sprint 1 contracts cover **every** Sprint 1 endpoint up front (DECISIONS D5): later builders won't change this package.

## What to put in the package (`src/`)
1. `errors.ts`: error code list (a `z.enum` + type) and the error response shape
   `{ error: { code: ErrorCode, message: string, details?: unknown, requestId?: string } }`, plus a map `errorCodeHttpStatus: Record<ErrorCode, number>`.
   Codes must include:
   - generic: `BAD_REQUEST`, `VALIDATION_FAILED`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `UNPROCESSABLE_ENTITY`, `TOO_MANY_REQUESTS`, `INTERNAL`, `IDEMPOTENCY_CONFLICT`
   - the existing API auth codes (see `EcoFin-API/src/utils/errors.ts`, read only): keep them, but drop the `LICENSE_*` ones only if nothing in F04 needs them (say what you dropped)
   - auth/session: `INVALID_CREDENTIALS`, `ACCOUNT_DISABLED`, `SHOP_INACTIVE`, `SUBSCRIPTION_EXPIRED`, `SHOP_SELECTION_REQUIRED`, `SHOP_NOT_ALLOWED`, `TOKEN_EXPIRED`, `TOKEN_INVALID`, `TOO_MANY_LOGIN_ATTEMPTS`
   - **every** code the baseline SQL raises: search `EcoFin-API/supabase/migrations/20261002000000_v1_baseline.sql` for `RAISE EXCEPTION` (don't read the file whole). That includes `APPEND_ONLY`, `AUDIT_NO_ORG`, `BRANCH_DENIED`, `BRANCH_NOT_IN_ORG`, `BRANCH_REQUIRED`, `CASH_ACCOUNT_INACTIVE`, `DAY_CLOSED`, `DOCUMENT_FINAL`, `FROZEN_ROW`, `FUTURE_BUSINESS_DATE`, `INSUFFICIENT_FUNDS`, `INSUFFICIENT_STORE_CREDIT`, `NOT_AN_EMPLOYEE`, `NOT_ENOUGH_STOCK_TO_RESERVE`, `NO_DELETE`, `ORG_NOT_ACTIVE`, `OUT_OF_STOCK`, `PERMISSION_DENIED`, `RESERVATION_CLOSED`, `UNIT_ALREADY_IN_STOCK`, `UNIT_NOT_ALLOWED`, `UNIT_NOT_AVAILABLE`, `UNIT_NOT_AVAILABLE_TO_RESERVE`, `UNIT_PRODUCT_MISMATCH`, `UNIT_REQUIRED`, `UNKNOWN_PERMISSION`, plus any in the 16 `RAISE EXCEPTION '%...'`-style lines you can identify.
   - a test that extracts every `RAISE EXCEPTION '<CODE>` code from the baseline SQL and checks each one is in the enum.
2. `roles.ts`: `employee_role` enum values **exactly** as in the baseline (`CREATE TYPE public.employee_role`), plus `SUPER_ADMIN` as a separate platform-role constant if the baseline models it differently (check how and say so).
3. `permissions.ts`: the 61 permission keys **exactly** as seeded (`INSERT INTO public.permissions` around line 3363), as a `const` tuple + `z.enum` + type, with module and description. Also the role → default keys map exactly as `INSERT INTO public.role_permissions` seeds it.
   **Parity test (required):** reads the baseline SQL (path from env `ECOFIN_BASELINE_SQL`, default `../EcoFin-API/supabase/migrations/20261002000000_v1_baseline.sql` relative to the package root), parses the permission keys and the role defaults, and checks they match the package exactly (same set, same count = 61). If the file isn't found, the test **fails** with a clear message saying where it looked.
4. `common.ts`: `Uuid`, `Money` (decimal **string** matching `numeric(18,2)`, e.g. `/^-?\d{1,16}(\.\d{1,2})?$/`; never `number`), ISO timestamp, business `date`, pagination query (`page`, `pageSize` ≤ 100) and paginated response wrapper, `IdempotencyKey` header schema.
5. Endpoint schemas, one module per area, each exporting `{ body?, query?, params?, response }` zod schemas + inferred types, named `<Area><Action>`:
   - `auth.ts` (F04): login body `{ identifier, password, tenantSlug? }`. `identifier` is an email or a username (`employees.username`, unique **per shop**, pattern `^[a-z0-9._-]{3,32}$`). `tenantSlug` (pattern from `organizations.tenant_slug`) is required when `identifier` isn't an email: use a zod refinement. Login response: access token, refresh token, expires at, user, `mustChangePassword`, and the list of shops `{ orgId, orgName, tenantSlug, role }` with `requiresShopSelection` when the login has several. Also: select shop (`orgId`; the API sends it to the DB as the `x-org-id` header), refresh, logout, forgot password (`identifier` + optional `tenantSlug`), reset password (recovery token + new password), change password (current + new; the baseline has `employees.must_change_password`), me (current employee, org, role, branches, `mustChangePassword`). Password rules: min 8, max 72 (bcrypt limit). The old license / activate-workspace endpoints are **not** in Sprint 1: don't add contracts for them.
   - `permissions.ts` or `access.ts` (F06): `GET /me/permissions` response (keys + branch ids + `allBranches` flag); set employee permission override (`employeeId`, `permissionKey`, `granted: boolean`, `reason`); assign employee branches (`employeeId`, `branchIds[]`). Columns from `employee_permission_overrides` and `employee_branches` in the baseline. Search, don't read whole.
   - `audit.ts` (F07): audit search query (date range, actor employee, action, entity type, entity id, branch, pagination) and response rows. Columns from `audit_log` in the baseline.
   - `health.ts` (F08): health response `{ status: 'ok' | 'degraded', db: 'ok' | 'down', version, time }`.
   Use the data model doc (`EcoFin-API/docs/EcoTech_Pro_Data_Model.md` §1, §2, §12, plus the tables named above) and the slices doc (F04, F06, F07, F08) for names. If a field you need isn't in the baseline or the docs, **stop and ask**. Don't invent business fields.
6. `index.ts`: re-exports everything, plus `CONTRACTS_VERSION = '0.1.0'` (a test checks it equals `package.json` version).
