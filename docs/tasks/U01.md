## Goal
Owners and branch managers add, edit, deactivate and restore the suppliers the shop buys from. Everyone who works with purchases (warehouse, accountant) can look them up and open a **supplier statement**: invoices, payments and returns with a running balance, ending at what the shop owes.

## Slice text (U01)
- **Includes:** create, edit, deactivate; name, phone, tax number, address, payment terms; supplier statement: invoices, payments, returns, balance owed.
- **Done when:** the statement balance equals invoices − payments − returns.

The invoice, payment and return screens come later (U02, U03, U04). This task proves the statement in SQL by inserting approved invoices, payments, a payment reversal and returns **directly as the superuser** in the test, as `i01_stock_view_test.sql` did for stock movements.

## Decisions already made (don't change them; record them in D53)
1. **Names and phones are unique among active suppliers**, case-insensitive and trimmed. Archived suppliers don't block a name or phone. Errors: `SUPPLIER_NAME_TAKEN`, `SUPPLIER_PHONE_TAKEN`.
2. **Deactivate (archive)** is refused while the supplier has a balance ≠ 0 (`SUPPLIER_HAS_BALANCE`) or open documents (`SUPPLIER_HAS_OPEN_DOCUMENTS`): invoices in `draft` / `pending_approval`, or purchase orders in `draft` / `sent` / `partially_received`. Restore re-checks the name and phone rules.
3. **Who can read suppliers and statements:** anyone holding at least one of `supplier.manage`, `purchase.order_manage`, `purchase.invoice_create`, `purchase.invoice_approve`, `purchase.return_create`, `supplier.payment_create`, `report.financial`. Writes need `supplier.manage`.
4. **A statement is shop-wide**: documents of every branch, since the supplier balance is shop-level. It isn't limited to the caller's branches.
5. The statement's balance must equal `public.v_supplier_balances.balance` (the baseline view). **Don't change that view**; read from it.

## Contract (`packages/contracts/src/suppliers.ts`, new; contracts 0.21.0)
- `Supplier`:
  - `{ id, name, phone: string|null, tax_registration_no: string|null, address: string|null, payment_terms_days: int, notes: string|null, archived_at: IsoTimestamp|null, created_at, updated_at, balance: Money }`
  - `balance` comes from `v_supplier_balances`; positive means the shop owes the supplier.
- `SupplierList = paginated(Supplier)`.
- `SupplierListQuery` (strict): `search?` (trim, ≤100; matches name ILIKE, or phone prefix), `status` (`active` default | `archived` | `all`), `page`, `pageSize`.
- `SupplierCreateBody` (strict):
  - **Required:** `name` (trim, 1–150).
  - **Optional:**
    - `phone`: trim; spaces and dashes removed; `^\+?[0-9]{6,15}$`; or null.
    - `tax_registration_no`: trim; `^[0-9-]{9,20}$`; or null.
    - `address` (≤300 | null) and `notes` (≤1000 | null).
    - `payment_terms_days`: int 0–365, default 0.
- `SupplierUpdateBody`: the same fields, all optional, strict, at least one key.
- `SupplierIdParams`: `{ id: Uuid }`.
- `SupplierStatementQuery` (strict): `from?`, `to?` (`BusinessDate`); `from ≤ to`.
- `SupplierStatement`:
  ```
  { supplier: Supplier, from: BusinessDate|null, to: BusinessDate|null,
    opening_balance: Money, closing_balance: Money,
    totals: { invoiced: Money, paid: Money, returned: Money },
    rows: [{ date: BusinessDate, kind: 'invoice'|'payment'|'payment_reversal'|'return',
             document_id: Uuid, number: string, reference: string|null, branch_id: Uuid,
             refund_mode: 'supplier_credit'|'cash'|null,
             debit: Money, credit: Money, balance: Money }] }
  ```
  `debit` raises what the shop owes (invoice, payment reversal); `credit` lowers it (payment, credit return). A **cash** return shows with debit 0 and credit 0: the supplier refunded money, so the balance doesn't change.
- New error codes in `errors.ts`:
  - `SUPPLIER_NOT_FOUND` (404)
  - `SUPPLIER_NAME_TAKEN` (409)
  - `SUPPLIER_PHONE_TAKEN` (409)
  - `SUPPLIER_HAS_BALANCE` (409)
  - `SUPPLIER_HAS_OPEN_DOCUMENTS` (409)
- Export from `index.ts`; bump to **0.21.0** (`package.json`, `CONTRACTS_VERSION`, root pin), and add a `CHANGELOG.md` entry.

## Part A: server + contracts
1. **Migration** `20261011090000_u01_suppliers.sql`:
   - Partial unique indexes on `public.suppliers`:
     - `(organization_id, lower(btrim(name))) WHERE archived_at IS NULL`
     - `(organization_id, phone) WHERE archived_at IS NULL AND phone IS NOT NULL`
     Map their unique violations to `SUPPLIER_NAME_TAKEN` / `SUPPLIER_PHONE_TAKEN`.
   - No new tables, columns or enums.
2. `app.can_read_suppliers()` → boolean: `app.has_permission` on any key of decision 3. No grants.
   Every read below starts with:
   - `app.current_employee_id() IS NULL` → `NOT_AN_EMPLOYEE`;
   - `NOT app.can_read_suppliers()` → `PERMISSION_DENIED: supplier.manage`.
3. `app.supplier_json(p_org, p_id)` → jsonb in the `Supplier` shape, with `balance` from `v_supplier_balances` (0 when no row) as a 2-decimal string. No grants.
4. `public.list_suppliers(p_search text, p_status text, p_limit int, p_offset int)` → `{items, total}`:
   - limits 1–100;
   - search: `name ILIKE '%…%'` (escape `% _ \` as in `list_stock`) or `phone LIKE '<digits>%'`;
   - status filter;
   - order by `name`, then `id`.
5. `public.get_supplier(p_id)`: another shop's or a missing id → `SUPPLIER_NOT_FOUND`. Archived suppliers are readable.
6. `public.supplier_statement(p_id uuid, p_from date, p_to date)` → `SupplierStatement`:
   - **Rows:**
     - approved invoices (`invoice_date`, debit = total, reference = `supplier_invoice_no`);
     - payments that are not reversals (`business_date`, credit = amount, reference = `reference`);
     - reversal rows (`reverses_payment_id IS NOT NULL`: kind `payment_reversal`, debit = amount);
     - returns (`business_date`, credit = total when `supplier_credit`, 0 and 0 when `cash`).
   - Draft, pending and rejected invoices **never** appear.
   - **Order:** date, then `created_at`, then `id`.
   - **Dates:** `opening_balance` = the net of every row dated before `p_from` (0 without `p_from`); rows are those within `[p_from, p_to]`; `closing_balance` = opening + the rows' net; each row's `balance` is the running total.
   - `totals` cover the rows shown.
   - `from > to` → `VALIDATION_FAILED`.
   - **Invariant (test it):** with no dates, `closing_balance` = `v_supplier_balances.balance` = invoices − payments − credit returns.
7. `public.create_supplier(p jsonb)` → jsonb (Supplier), `supplier.manage`:
   - allowed keys only (unknown → `VALIDATION_FAILED`);
   - trims, and normalises the phone (strip spaces and dashes);
   - validates the lengths and patterns of the contract (the DB repeats them);
   - audit `supplier.created` with after.
8. `public.update_supplier(p_id, p_changes jsonb)`, `supplier.manage`:
   - an archived supplier can't be edited (`SUPPLIER_NOT_FOUND`);
   - no actual change → no audit row; otherwise one `supplier.updated` with the changed keys before and after.
9. `public.set_supplier_archived(p_id, p_archived boolean)`, `supplier.manage`:
   - **Archive:** refused per decision 2. Same state again → no change, no audit.
   - **Restore:** the unique indexes apply (`SUPPLIER_NAME_TAKEN` / `SUPPLIER_PHONE_TAKEN`).
   - Audit `supplier.archived` (severity `warning`) or `supplier.restored`.
