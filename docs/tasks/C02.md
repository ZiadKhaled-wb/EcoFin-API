## Goal
An owner or branch manager can add, edit, archive and restore the products the shop sells, with prices, tax class, category and image. Barcodes are generated when left empty. Every employee can search the catalog, and the POS can find an active product by barcode or SKU. Archived products can't be sold but stay readable everywhere they were used.

## Slice text (C02)
- Fields: name (Arabic/English), SKU (unique per shop), barcode (unique per shop, auto-generated if empty), category, unit, cash price, installment price, cost (read-only, set by purchases), tax class, warranty months, "serialized" flag (each unit has a serial/IMEI), min stock level, image
- Supplier is **not** required (it belongs on the purchase)
- Archive instead of delete; archived products can't be sold but stay in history
- Price changes are audited

**Done when (slice):** a product can be created, found by barcode in the POS, archived, and still shows in old sales.

The POS screen (S06) and sales posting (S01) don't exist yet. This task proves "found by barcode in the POS" through the lookup endpoint the POS will call, and "still shows in old sales" in SQL, with a sale line inserted directly in the test.

## Contract (`packages/contracts/src/products.ts`, new; contracts **0.13.0**)
- `Product`:
  - Fields: `{ id, name_ar, name_en, sku, barcode, category_id, unit_of_measure, cash_price: Money, installment_price: Money | null, avg_cost: string (decimal, read-only), tax_class_id, warranty_months, is_serialized, min_stock, image_file_id, eta_item_code, eta_item_type, archived_at, created_at, updated_at }`.
  - `archived_at` is how archiving shows. `is_active` is **not** in the contract: it moves together with `archived_at`.
- `ProductList = paginated(Product)`.
- `ProductListQuery`:
  - `search?` (trimmed, ≤100)
  - `category_id?`
  - `include_subcategories?` (default `true`)
  - `status?` (`active` default | `archived` | `all`)
  - `page`, `pageSize` (from `PaginationQuery`)
- `ProductLookupQuery`: `{ code: string (trim, 1–64) }`.
- `ProductCreateBody` (strict):
  - **Required:** `name_ar` (trim, 1–150), `sku` (trim, 1–40, `^[A-Za-z0-9._/-]+$`, upper-cased), `cash_price` (Money ≥ 0).
  - **Optional:**
    - `name_en` (≤150 | null)
    - `barcode` (trim, 4–32, `^[0-9A-Za-z-]+$` | null; empty or null means generate)
    - `category_id` (Uuid | null)
    - `unit_of_measure` (trim, 1–20, default `piece`)
    - `installment_price` (Money ≥ 0 | null)
    - `tax_class_id` (Uuid; default: the shop's default class)
    - `warranty_months` (int 0–120, default 0)
    - `is_serialized` (default false)
    - `min_stock` (int 0–1,000,000, default 0)
    - `image_file_id` (Uuid | null)
    - `eta_item_code` (trim, 1–40 | null) and `eta_item_type` (`EGS` | `GS1` | null): both or neither
  - **Never** `avg_cost`, `organization_id`, `is_active` or `archived_at`. Strict schemas reject them.
- `ProductUpdateBody`: the create fields, all optional, strict, at least one key.
- `ProductIdParams`: `{ id: Uuid }`.
- New error codes:
  - `PRODUCT_NOT_FOUND` (404)
  - `PRODUCT_SKU_TAKEN` (409)
  - `PRODUCT_BARCODE_TAKEN` (409)
  - `PRODUCT_SERIAL_LOCKED` (409)
  - `PRODUCT_CATEGORY_ARCHIVED` (409)
- Reuse `TAX_CLASS_NOT_FOUND`, `CATEGORY_NOT_FOUND`, `FILE_NOT_FOUND`, `NAME_REQUIRED`, `VALIDATION_FAILED` and `PERMISSION_DENIED`.
- Export from `index.ts`; bump `CONTRACTS_VERSION`, `packages/contracts/package.json` and the root pin to **0.13.0**; add a `CHANGELOG.md` entry.

## Part A: server + contracts

1. **One migration** `supabase/migrations/<timestamp>_c02_products.sql`, numbered after the newest migration on `main` at merge time (D39; after C01's). Rule 11 for every function:
   - `SECURITY DEFINER`, `SET search_path = ''`
   - org from `app.current_org_id()`
   - `FOR UPDATE` on the rows it changes
   - one `app.write_audit(...)` with before/after
   - REVOKE from PUBLIC, anon and authenticated, then GRANT to authenticated (for `public.*`); `app.*` helpers get no grants
   - casts, CHECKs and unique violations mapped to contract codes, never raw messages
2. `public.list_products(p_search text, p_category_id uuid, p_include_children boolean, p_status text, p_limit int, p_offset int)` → jsonb `{items, total}`, STABLE, any employee:
   - `p_search` matches `name_ar ILIKE`, `name_en ILIKE`, `sku ILIKE` prefix and **exact** `barcode`.
   - `p_category_id` filters with `category_id = ANY(app.category_with_children(org, p_category_id))` when `p_include_children`, else `category_id = p_category_id`.
   - `p_status`: `active` means `archived_at IS NULL`; `archived`; `all`.
   - Order by `name_ar`, then `id`. Money and `avg_cost` as decimal strings (`::text`).
3. `public.get_product(p_id uuid)` (any employee, archived included; another shop's or a missing id → `PRODUCT_NOT_FOUND`).
   `public.lookup_product(p_code text)` (any employee) finds by exact `barcode` first, then exact `sku` (upper-cased). Only **active** products; otherwise `PRODUCT_NOT_FOUND`. This is what the POS calls.
4. `public.create_product(p jsonb)` → uuid, `catalog.manage`:
   - Allowed keys as in `ProductCreateBody`. Validate names and SKU (trim; SKU upper-cased).
   - SKU taken → `PRODUCT_SKU_TAKEN`; barcode taken → `PRODUCT_BARCODE_TAKEN`.
   - `tax_class_id` defaults to `org_settings.default_tax_class_id`. A class that's missing, in another shop or archived → `TAX_CLASS_NOT_FOUND`.
   - `category_id`, when given: another shop's or missing → `CATEGORY_NOT_FOUND`; archived → `PRODUCT_CATEGORY_ARCHIVED`.
   - `image_file_id`, when given, must be a `files` row of this shop with `purpose = 'product_image'` (else `FILE_NOT_FOUND`).
   - `eta_item_code` and `eta_item_type` are both set or both null (else `VALIDATION_FAILED`).
   - `is_active = true`, `avg_cost = 0`.
5. **Generated barcode** (empty or null barcode on create):
   - An in-store EAN-13: `'2'` + 11 random digits + the EAN-13 check digit.
   - On a unique violation of `products_barcode_idx`, retry with new digits up to 5 times, then raise `PRODUCT_BARCODE_TAKEN`.
   - Put the check-digit calculation in its own `app.ean13_check_digit(text)` helper (IMMUTABLE, no grants) and test it on known codes (e.g. `400638133393` → `1`).
6. `public.update_product(p_id uuid, p_changes jsonb)`, `catalog.manage`:
   - Allowed keys as in `ProductUpdateBody`. Unknown key (including `avg_cost`) → `VALIDATION_FAILED`.
   - Missing or another shop's id → `PRODUCT_NOT_FOUND`. An archived product can't be edited (`PRODUCT_NOT_FOUND`; restore it first).
   - The same validations as create. Setting `barcode` to empty or null **generates** a new one.
   - **Price rule:** if `cash_price` or `installment_price` actually changes, also call `app.require_permission('catalog.price_change')`. The audit action is then `product.price_changed`, with before/after of **all** changed keys; otherwise it's `product.updated`. One audit row per call; no change, no row.
   - **Serialized lock:** `is_serialized` can't change once the product has any `units` row or any `stock_movements` row (`PRODUCT_SERIAL_LOCKED`).
7. `public.set_product_archived(p_id uuid, p_archived boolean)`, `catalog.manage`:
   - Same state already → do nothing, write no audit.
   - Archive sets `archived_at = now()` and `is_active = false`. Restore clears both.
   - Restore is refused if the product's category is archived (`PRODUCT_CATEGORY_ARCHIVED`) or its tax class is archived (`TAX_CLASS_NOT_FOUND`).
   - Archiving is allowed even with stock on hand (the client asks for confirmation).
   - Severity: `warning` for archive, `info` for restore.
8. **API:**
   - `src/services/products.service.ts` (+ unit test), `src/controllers/products.controller.ts`, `src/routes/products.ts` (`validate({ query | params | body })`, one access marker per route), mounted at `/api/products` in `src/app.ts`.

   - Regenerate `src/types/database.types.ts` (`npm run db:types`).
   - Add the 7 endpoints to `src/docs/openapi.ts`.

   - Audit drivers in `audit.integration.test.ts`.
   - Denial cases in `tenant_and_permission_test.sql` for `create_product`, `update_product`, `set_product_archived` (`catalog.manage`). Add `list_products`, `get_product` and `lookup_product` to the excluded read functions and to `security_guards_test.sql`'s `t.no_permission_ok`, each with a reason.
