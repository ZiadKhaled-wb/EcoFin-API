## Goal
A manager or warehouse keeper orders goods from a supplier before they arrive (a purchase order), sends it, and later receives it through purchase invoices made **from the order**. The order tracks what has arrived and what is still to come. Low stock (I06) can start an order in one click, and a customer's special order line can point to the purchase order that will fill it.

## Slice text (U05)
- **Includes:** order lines and expected prices; states draft → sent → partly received → received / cancelled; create a purchase invoice from an order (U02) and track what's still to come; furniture special orders (S10) can create a purchase order.
- **Done when:** receiving part of an order leaves the rest open; a special customer order shows its purchase order status.

## Decisions already made (record them in D56)
1. **User decision: no over-receipt.**
   - An invoice line linked to an order line can't exceed what is still to come on it.
   - Checked when the draft is saved, **and again at approval** (two drafts could each claim the rest) → `PO_OVER_RECEIPT`, details `{ po_line_id, remaining }`.
   - Extra goods go on a separate invoice line without the order link.
2. **"Received" means approved.** Only **approved** invoices count as received (baseline view `v_po_line_received`). Drafts and pending invoices don't.
3. **Statuses:**
   - `draft` → `sent` (Send).
   - On approving an invoice of the order: every line's remaining = 0 → `received`; else, if anything was received → `partially_received`.
   - **Cancel** works from `draft`, `sent` or `partially_received` (a reason is required) and closes what's left. `received` and `cancelled` are final.
4. **Invoicing an order:**
   - Only a `sent` or `partially_received` order can be invoiced: `draft` → `PO_NOT_SENT`; `received` / `cancelled` → `PO_CLOSED`.
   - The invoice gets the order's supplier and branch, which can't differ, and `po_id`.
   - Each linked invoice line must be the order line's product (`PO_LINE_MISMATCH`).
   - The draft's unit cost defaults to the line's expected cost (0 when none). The user edits the draft before approving.
5. **Special orders (S10 comes later):**
   - A PO line can be created for a customer order line by giving `sales_order_line_id`. The function sets `sales_order_lines.po_line_id` when that line is the shop's, `fulfilment = 'to_order'`, the same product, its order still `open`, and the line not already linked. Otherwise → `SALES_ORDER_LINE_INVALID`.
   - The order's detail lists the linked customer orders.
   - `app.sales_order_line_po_status(p_org, p_line_id)` returns `{po_id, number, status, ordered, received, remaining}` for S10 to show.
6. **Low stock (D52):** on the stock page with "Low stock only" and one branch selected, a **"Create purchase order"** button opens the new-order form for that branch, pre-filled with every low product and quantity = min level − available. The supplier is chosen by the user. The I06 dashboard card gets the same button, per branch.
7. **Permissions:**
   - Orders: `purchase.order_manage` (WAREHOUSE, BRANCH_MANAGER; OWNER).
   - **Invoicing an order:** `purchase.invoice_create`.
   - Reads: `app.can_read_suppliers()` (U01), within the caller's branches.

## Database facts (baseline; don't alter)
- `purchase_orders`: `number` (prefix PO via `next_document_number(org, branch, 'purchase_order')`), `supplier_id`, `branch_id`, `status` (`po_status`), `expected_date`, `notes`, `idempotency_key`. Frozen at `received` / `cancelled`. Lines are frozen from `partially_received` on.
- `purchase_order_lines`: `po_id`, `product_id`, `quantity > 0`, `expected_unit_cost ≥ 0` (nullable).
- `purchase_invoices.po_id`, `purchase_invoice_lines.po_line_id`: exist since the baseline; U02 left them NULL.
- `v_po_line_received`: `received` and `remaining` per order line, approved invoices only.
- `sales_order_lines.po_line_id`, `fulfilment ('from_stock'|'to_order')`; `sales_orders.status` (`order_status`: open, partially_delivered, delivered, cancelled). No functions write sales orders yet. The SQL test inserts one directly.

## Contract (contracts 0.24.0; `packages/contracts/src/purchases.ts`)

- `PurchaseOrderLineInput` (strict): `product_id`, `quantity` (1–100 000), `expected_unit_cost?: Money | null`, `sales_order_line_id?: Uuid`.
- `PurchaseOrderCreateBody` (strict): `supplier_id`, `branch_id`, `expected_date?: BusinessDate|null`, `notes?` (≤1000), `lines` (1–200, each product at most once).
- `PurchaseOrderUpdateBody` (strict): `expected_date?`, `notes?`, `lines?`; at least one key. Drafts only.
- `PurchaseOrderCancelBody` (strict): `reason` (trim, 3–500).

- `PurchaseOrder`: `{ id, number, supplier_id, supplier_name, branch_id, status, expected_date, notes, created_by_name, created_at, updated_at, lines, invoices: [{ id, number, status, total }] }`.
- `PurchaseOrderSummary`, `PurchaseOrderList`, `PurchaseOrderListQuery` (`supplier_id?`, `branch_id?`, `status?`, `search?` (number), paging).
