## Goal
A salesperson gives a customer a written price offer before they decide, mostly for furniture made to order. A quotation has lines (stock products priced by the server, or custom items with a description and a price), free-text notes per line (fabric, size, colour), discounts within the caller's cap, VAT, a validity date and a QT number. It moves draft → sent → accepted / expired / cancelled, prints on A4 in Arabic or English, and **never** touches stock, cash or tax ledgers. Accepting freezes it; S10 will later turn an accepted quote into an order with the same lines and prices.

## Slice text (S09)
- **Includes:** lines with prices and notes (e.g. fabric, size), validity date, print/share as PDF; states: draft → sent → accepted (converts to an order, S10) / expired / rejected; no stock or money effect.
- **Done when:** accepting a quote creates an order with the same lines and prices. *(S10 is not built: S09's part is that an accepted quote's lines and prices are frozen and readable in one call; S10 proves the order.)*

## Decisions (record them in D73; the ones marked *to confirm* are defaults: list them in your summary and in a Jira comment for the owner before Part B)
1. **Who (no new permission keys):** writes = `quotation.manage` (OWNER, BRANCH_MANAGER, CASHIER have it), plan module `sales`, `app.require_branch_access(branch_id)`. Reads = any of `quotation.manage`, `sale.create`, `order.manage`, only for the caller's branches (OWNER: all). An expired shop reads but can't write.
2. **Pricing without stock:** a new helper `app.quotation_cart(p_org, p_branch, p_lines, p_can_override, p_sale_discount)` prices product lines like `app.sale_cart` (list price, `price.override` for another price, T01 tax, S03 discounts spread over lines) but **does not check or lock stock and takes no serials** (a quote reserves nothing). Factor the shared part out of `app.sale_cart` only if you can do it without changing any sale result (S01/S02/S03 tests must stay green); otherwise write the helper next to it and say so.
3. **Custom lines** (`product_id` NULL): `description` required (2–200), `unit_price` entered by the user (≥ 0.01), taxed with `org_settings.default_tax_class_id` (*to confirm*), no `price.override` needed. A custom line must become a product before it is ordered (Data Model open point, S10's job).
4. **Discounts:** line and whole-quote discounts as S03 (amount or %); each line within the caller's cap (`app.discount_cap_pct`) unless the caller has `discount.above_cap`; above it → `DISCOUNT_ABOVE_CAP` (no on-the-spot approval for quotes, *to confirm*). Reason not required on a quote.
5. **Numbers and dates:** QT number from `app.next_document_number(org, branch, 'quotation')` at create (drafts are numbered; a cancelled draft keeps its number). `valid_until` required, default today + **14** days in the shop timezone (*to confirm*), must be ≥ today and ≤ today + 365.
6. **States:**
   - `draft`: edit everything (header and lines; lines are replaced whole on update), `customer_id` optional.
   - `send`: draft → `sent`; needs a customer (*to confirm*) and at least one line; prices are **recomputed** at send time and the totals frozen from then on (a price change after sending doesn't change the quote).
   - `sent` can't be edited; to change it: cancel and **copy** (decision 8).
   - `accept`: sent → `accepted`, only while `valid_until ≥ today` else `QUOTATION_EXPIRED`.
   - `cancel` with `outcome` `rejected` (the customer said no) or `withdrawn` (the shop withdrew it) and an optional reason: draft or sent → `cancelled`; the outcome and reason are kept in the audit row and returned as `cancel_outcome` / `cancel_reason` from the latest `quotation.cancelled` audit row (no new column). The screen shows "Rejected" or "Cancelled".
   - `expired`: set by the daily job `quotations.expire` (F13, per shop at local midnight) for `sent` quotes with `valid_until < today`; reads also return `is_expired: true` for a sent quote past its date before the job ran. Drafts never expire.
   - Same state again → no change, no audit row. Any other move → `QUOTATION_STATUS_INVALID` with `{ from, to }`.
7. **No stock or money effect:** no function in this task writes `stock_movements`, `cash_movements`, `payments`, `payment_allocations`, `fiscal_submissions`, reservations or `store_credit_movements`; the SQL test proves the counts don't move.
8. **Copy:** `POST /api/quotations/:id/copy` creates a new draft with the same customer, branch, notes and lines (prices recomputed now, new number, new `valid_until` default). Works from any state.
9. **Idempotency:** create and copy take `idempotency_key` (8–128); the same key returns the same quote.
10. **For S10:** `app.quotation_for_order(p_org uuid, p_id uuid) RETURNS jsonb` returns an accepted quote's header and frozen lines exactly as stored (not granted to `authenticated`); `GET /api/quotations/:id` returns the same lines.
11. **Audit actions:** `quotation.created`, `quotation.updated`, `quotation.sent`, `quotation.accepted`, `quotation.cancelled` (`outcome`, `reason`), `quotation.expired` (written by the job, actor null), `quotation.copied` (on the new quote, `from_id`). Entity type `quotation`.

## Contract (`packages/contracts/src/quotations.ts`, new; contracts 0.43.0)
- `QuotationStatus = z.enum(['draft','sent','accepted','expired','cancelled'])`; `QuotationCancelOutcome = z.enum(['rejected','withdrawn'])`.
- `QuotationLineInput` (strict): `{ product_id?: Uuid, description?: string, custom_notes?: string (≤ 500), quantity: int > 0, unit_price?: Money (custom lines, or with price.override), discount?: Discount }` (refine: product or description; `Discount` reused from S03's contract).
- `QuotationLine`: `{ line_no, product_id|null, product_name|null, sku|null, description|null, custom_notes|null, quantity, unit_price, discount_amount, tax_amount, line_total }`.
- `Quotation`: `{ id, number, status, is_expired, branch: { id, name }, customer: { id, full_name, phone }|null, valid_until: IsoDate, notes|null, subtotal, discount_total, tax_total, total, lines: QuotationLine[], cancel_outcome|null, cancel_reason|null, created_by_name, created_at, updated_at, sent_at|null, decided_at|null }` (`sent_at` / `decided_at` and the cancel fields come from the audit rows; no new columns).
- `QuotationListQuery = PaginationQuery.extend({ status?: QuotationStatus | 'open', branch_id?, customer_id?, search? (number or customer name/phone), from?, to? })` (`open` = draft + sent); `QuotationList = paginated(Quotation without lines + lines_count)`.
- `QuotationCreateBody` (strict): `{ branch_id, customer_id?, valid_until?, notes?, lines (1–100), sale_discount?, idempotency_key }`; `QuotationUpdateBody` (strict, at least one key): the same minus `branch_id` and `idempotency_key`; `QuotationPreviewBody` = create body minus `idempotency_key`; `QuotationPreview` = the priced lines and totals.
- `QuotationCancelBody` (strict): `{ outcome: QuotationCancelOutcome, reason?: string (≤ 300) }`; `QuotationCopyBody` (strict): `{ idempotency_key }`.
- New error codes (`errors.ts`): `QUOTATION_NOT_FOUND` (404), `QUOTATION_STATUS_INVALID` (409), `QUOTATION_EXPIRED` (409), `QUOTATION_NOT_EDITABLE` (409), `QUOTATION_CUSTOMER_REQUIRED` (409), `QUOTATION_EMPTY` (409). Reuse `PRODUCT_NOT_FOUND`, `CUSTOMER_NOT_FOUND`, `DISCOUNT_ABOVE_CAP`, `PERMISSION_DENIED`, `BRANCH_DENIED`, `VALIDATION_FAILED`.
