## Goal
One shop can never see or change another shop's data through the API, a file or an export, and CI fails when someone adds an endpoint without a cross-shop test.

## Slice text (F05)
- Middleware that loads the user and their `organization_id` once per request; every query is scoped by it
- Every foreign id in a request (product, vault, customer, invoice…) is checked to belong to the same shop
- Request bodies are whitelisted by the contract (F03); fields like `organization_id` can never be set by the client
- Database grants removed from the `anon` and `authenticated` roles; the frontend never talks to the database directly
- Private file storage paths include the org id
- An automated test suite that creates two shops and tries to read and write across them through **every** endpoint, file and export
**Done when (slice):** the cross-shop test suite runs in CI and passes; adding a new endpoint without a cross-shop test fails a CI check.

## What exists after waves 1–2
F04's `authenticate` puts `{ userId, accessToken, orgId? }` on `req`, and `supabaseForRequest(token, orgId?)` makes a per-request client. F08 has `mapDbError`, the error handler and the contract error shape. The DB already scopes reads by RLS (`app.current_org_id()`), uses composite FKs `(id, organization_id)`, and grants no table writes to `anon`/`authenticated` (data model §2; the smoke test checks part of this). The bucket `tenant-files` is private, and `files.path` must start with `<org id>/`.

## Behaviour
1. **Request context** `loadRequestContext` (after `authenticate`): with the user's client, load the caller's employee for the active shop **once** (id, org id, role, active, default branch, branch ids) and set `req.ctx = { userId, employeeId, orgId, role, branchIds, db }`, where `db` is the per-request client. No employee for the chosen shop → 403 `NOT_AN_EMPLOYEE` (or `SHOP_SELECTION_REQUIRED` when several shops and no `x-org-id`). Handlers use `req.ctx.db` and `req.ctx.orgId` only. Add a typed `getCtx(req)` that throws if the middleware didn't run.
2. **Never trust org from the client:** a middleware rejects any request whose body, query or params contain `organization_id` / `organizationId` / `orgId` (except `x-org-id` on the auth select-shop flow) with 400 `VALIDATION_FAILED`. `validate({ body, query, params })` parses with the contract schemas (strict), so unknown keys → 400, and handlers get the parsed values only.
3. **Foreign ids:** `assertSameOrg(ctx, table, ids)` selects the ids through `ctx.db` (RLS scoped) and returns 404 `NOT_FOUND` if any are missing, so another shop's id looks like a non-existent one. Keep a small allow-list of tables it accepts (no string-built SQL from user input).
4. **Storage paths:** `tenantFilePath(ctx, ...segments)` always builds `<orgId>/<segments>`, rejects `..`, absolute paths and empty segments; a reader helper refuses paths whose first segment isn't `ctx.orgId`. In the **new** migration `supabase/migrations/20261003080000_f05_tenant_storage.sql`: `storage.objects` policies for bucket `tenant-files` so `authenticated` can `SELECT` only objects whose first folder is `app.current_org_id()::text`, with no INSERT/UPDATE/DELETE for `authenticated` (uploads come later in F14, through the API). If `storage` isn't present in plain Postgres CI, guard it the way the baseline does (`to_regclass('storage.objects')`).
5. **Grant check (DB):** add `supabase/tests/f05_tenant_test.sql`: for **every** table in `public` with an `organization_id` column, assert `anon` and `authenticated` have no INSERT/UPDATE/DELETE, and that `authenticated` with shop A's JWT claims sees zero rows of shop B (loop over the tables; seed two shops in the test like the smoke test does). Also check the storage policy.
6. **Cross-shop suite + CI gate:**
   - `src/test/cross-shop/` holds a small harness: `crossShopCase({ method, path, ... })` registers a case that, under `RUN_INTEGRATION=1`, logs in as a user of shop A and tries to read and write shop B's resources (ids from the seed), expecting 404/403 and no change.
   - Write cases for **every** route that exists now (auth `me`, `select-shop`, `change-password`, `logout`, health is public).
   - `scripts/check-cross-shop.ts` (+ npm script `check:cross-shop`, + a CI step): build the app with `createApp()`, list every registered route (method + path), compare with the registered cross-shop cases plus an explicit `PUBLIC_ROUTES` allow-list (health, login, refresh, forgot, reset), and **exit 1** naming any route without a case. A unit test runs the same check, so `npm test` fails too.
