## Goal
An owner or branch manager can create, rename, nest (one level), archive and restore product categories. Every employee can read them. The database gives later slices (C02 products, S06 POS, D reports) one helper to filter "this category and its subcategories".

## Slice text (C01)
Groups products. Create, edit, archive; name unique per shop; optional parent category (one level); can't archive a category that still has active products without moving them.
**Done when (slice):** products can be filtered by category in the catalog, POS and reports.

Products, POS and reports don't exist yet (C02, S06, D01–D03). This task therefore delivers the category side plus the filter helper, and **proves the filter in SQL** with products inserted directly in the test. C02 and the others must use the helper (see Behaviour 8).

## Behaviour (server)
1. **One migration** `supabase/migrations/<timestamp>_c01_categories.sql`, numbered **after the newest migration on `main` at merge time** (today that's `20261007100000`; rule D39, checked in CI by `scripts/check-migration-order.mjs`). Never edit an old migration.
2. **Every function** follows rule 11 of `ecotech-build`:
   - `SECURITY DEFINER`, `SET search_path = ''`
   - the org from `app.current_org_id()`, never from a parameter
   - row locks (`FOR UPDATE`) on what it changes
   - one `app.write_audit(...)` with before/after
   - `REVOKE ALL … FROM PUBLIC, anon, authenticated` then `GRANT EXECUTE … TO authenticated` for `public.*`; `app.*` helpers get no grants
   - CHECK, cast and unique errors are mapped to contract codes, never raw messages
3. `public.list_categories()` (STABLE; any employee, else `NOT_AN_EMPLOYEE`):
   - Returns jsonb: an array of `Category` objects for the caller's shop.
   - Order: active first, then archived. Within each, parents in name order, each followed by its children in name order.
   - `active_product_count` = active products in **that** category (not counting children).
4. `public.create_category(p_name text, p_parent_id uuid DEFAULT NULL)` → uuid, `catalog.manage`:
   - Name: trimmed, 1–60 characters, else `NAME_REQUIRED`. Already used in the shop, archived categories included, → `CATEGORY_NAME_TAKEN`.
   - Parent, when given, must be in the same shop (else `CATEGORY_NOT_FOUND`), active (else `CATEGORY_PARENT_ARCHIVED`), and itself top-level (`parent_id IS NULL`, else `CATEGORY_DEPTH`).
5. `public.update_category(p_id uuid, p_changes jsonb)`, `catalog.manage`:
   - Keys allowed: `name`, `parent_id`. Unknown key → `VALIDATION_FAILED`.
   - Another shop's id or a missing id → `CATEGORY_NOT_FOUND`. An archived category can't be edited (`CATEGORY_NOT_FOUND`; restore it first).
   - Name rules as in 4.
   - Setting `parent_id`:
     - The parent can't be itself (`CATEGORY_DEPTH`).
     - The parent must be top-level, active and in the same shop (same errors as 4).
     - A category that **has children** can't become a child (`CATEGORY_DEPTH`): one level only.
   - `parent_id: null` makes it top-level.
   - No change at all → no update, no audit row.
6. `public.set_category_archived(p_id uuid, p_archived boolean, p_move_to uuid DEFAULT NULL)`, `catalog.manage`:
   - Same state already → do nothing and write no audit.
   - **Archive:**
     - If the category has **active child categories** → `CATEGORY_IN_USE`, with `DETAIL` jsonb `{"active_products": n, "active_children": m}`.
     - If it has **active products**:
       - Without `p_move_to` → `CATEGORY_IN_USE` with the same detail.
       - With `p_move_to` → that target must be another active category in the same shop (else `CATEGORY_NOT_FOUND`, or `CATEGORY_PARENT_ARCHIVED` for an archived one). Move all active products to it (`UPDATE products SET category_id = p_move_to`) **in the same transaction**, then archive. The audit `after` includes `moved_products` and `moved_to`.
   - **Restore:** if its parent is archived → `CATEGORY_PARENT_ARCHIVED`.
   - Audit severity: `warning` for archive, `info` for restore.
7. **API layer:**
   - `src/services/categories.service.ts` (uses `ctx.db.rpc`, parses with the contract, returns the one changed category by re-reading the list).
   - `src/controllers/categories.controller.ts`.
   - `src/routes/categories.ts` with `validate(...)` and exactly one access marker per route.
   - Mount in `src/app.ts` with `mountRouter(app, '/api/categories', …)`.
   - `mapDbError` must expose `CATEGORY_IN_USE`'s detail: add it to the validated-details list in `src/utils/errors.ts`, with a contract schema `CategoryInUseDetail { active_products, active_children }`, as was done for `BRANCH_DEACTIVATE_NEEDS_CONFIRM`.
   - Regenerate `src/types/database.types.ts` (`npm run db:types`, local stack).
8. **The filter helper (the slice's "Done when"):** `app.category_with_children(p_org uuid, p_category_id uuid) RETURNS uuid[]` (STABLE, `SECURITY DEFINER`, no grants).
   - Returns the category id plus the ids of its child categories in that shop. An unknown id or another shop's id → empty array.
   - Later slices filter products with `category_id = ANY(app.category_with_children(org, :id))`. Write that rule in the migration comment and in DECISIONS.
9. **Registries (D19: CI fails without them):**
   - `src/test/audit-registry/registry.ts`: the 4 write routes with their actions.
   - `src/test/cross-shop/cases.ts`: one case per route (5). A foreign `x-org-id` → 403; another shop's category id → 404 `CATEGORY_NOT_FOUND`; an injected `organization_id` in a body → 400; no audit row in shop B.
   - `src/test/cross-shop/check.test.ts`: the route count goes from **54 to 59**, and add the 5 keys to its list.
   - `src/routes/audit.integration.test.ts`: a driver per write route. Use unique names per run, e.g. `` `F07 ${STAMP}-${ipCounter}` ``.
   - `supabase/tests/tenant_and_permission_test.sql`: denial cases for `create_category`, `update_category`, `set_category_archived` (`catalog.manage`). Add `list_categories` to the excluded read functions.
   - `supabase/tests/security_guards_test.sql`: add `list_categories` to `t.no_permission_ok` with a one-line reason (read-only, any employee).
   - `src/docs/openapi.ts`: the 5 endpoints (short, like `/api/tax-classes`).
