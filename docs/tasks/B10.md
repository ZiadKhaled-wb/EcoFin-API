## Goal
Every endpoint checks a permission key from the shared list; the owner can add or remove a permission per employee and set their branches; the client can ask "can I?" from the same keys.

## Slice text (F06)
- Roles: Owner, Branch Manager, Cashier, Warehouse, Collector, Accountant, Lawyer (plus Super Admin at platform level)
- Each role has a default set of permissions; the owner can add or remove permissions per employee
- Action permissions, not just pages
- Branch scope: an employee works in their assigned branches only; the owner sees all
- The server checks every endpoint; the client hides what the user can't do
**Done when (slice):** each permission has a test proving a user without it gets 403; the client and server use the same permission keys from F03.

## Database facts (baseline, already there; don't recreate)
`permissions` (61 keys), `role_permissions` (defaults; OWNER has everything), `employee_permission_overrides (organization_id, employee_id, permission_key, granted)` PK `(employee_id, permission_key)`, `employee_branches (organization_id, employee_id, branch_id)`. Helpers `app.has_permission(key)` (granted to `authenticated`), `app.require_permission(key)` (raises `PERMISSION_DENIED: key`, `NOT_AN_EMPLOYEE`, `ORG_NOT_ACTIVE`, `UNKNOWN_PERMISSION`), `app.has_branch_access(branch)`, `app.require_branch_access(branch)` (raises `BRANCH_DENIED`), `app.write_audit(...)`. Permission key for managing employees: `employee.manage`.

## Contract
`@ecotech/contracts` access/permissions module: `GET /api/me/permissions` response; set override `{ permissionKey, granted, reason }` on `PUT /api/employees/:employeeId/permissions`; assign branches `{ branchIds, reason }` on `PUT /api/employees/:employeeId/branches`. Use the contract's paths if it defines them. If a schema is missing, **stop and report**.

## Behaviour (server)
1. **New migration** `supabase/migrations/20261003100000_f06_permissions.sql` (rule 11 for each function: `SECURITY DEFINER`, `SET search_path = ''`, first line `v_emp := app.require_permission('employee.manage')`, org from `app.current_org_id()`, never from parameters, row locks, one `app.write_audit(...)` with before/after and the **required** `reason` (empty reason → error), `GRANT EXECUTE … TO authenticated`):
   - `public.my_permissions()` (STABLE, no permission needed): the caller's effective keys (role defaults ± overrides; OWNER = all) + branch ids + `all_branches` (OWNER).
   - `public.set_employee_permission(p_employee_id uuid, p_permission_key text, p_granted boolean, p_reason text)`: upsert the override. The target employee must be in the caller's org (composite FK + explicit check → `NOT_FOUND`). Can't change the OWNER's permissions or your own. Granting a key equal to the role default removes the override row instead of storing a redundant one. If you think one of these rules isn't supported by the docs, **stop and ask** rather than inventing.
   - `public.set_employee_branches(p_employee_id uuid, p_branch_ids uuid[], p_reason text)`: replace the set; every branch must be in the org (`BRANCH_NOT_IN_ORG`).
   - These are settings, not money or stock documents: they're idempotent by design (set semantics). Say so in the plan instead of adding an idempotency key.
2. **Permission middleware** `requirePermission(key: PermissionKey)` (type from contracts): asks the DB through `req.ctx.db.rpc('has_permission', …)` (or reads `my_permissions()` once per request and caches it on `req.ctx`) → 403 `PERMISSION_DENIED` with the key in `details`. A route without a permission must be impossible to forget: add `requirePermission` (or an explicit `publicRoute()` / `authenticatedOnly()` marker) to **every** existing route, and extend the F05 route check (`scripts/check-cross-shop.ts` or a sibling `check-permissions`) so a route with no marker fails CI.
3. **Endpoints:** `GET /api/me/permissions` (authenticated only), `PUT /api/employees/:employeeId/permissions` and `PUT /api/employees/:employeeId/branches` (`employee.manage`), using F05's `validate` and `assertSameOrg`, mapping DB errors with `mapDbError`.
