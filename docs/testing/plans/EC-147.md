# EC-147: revoked POS device on an open shift

Decision 1 was corrected by the user: `app.current_device_id()` NULL means `DEVICE_REVOKED`; a different valid device means `DEVICE_MISMATCH`. A stale token after re-pairing is revoked.

API and web use `fix/ec-147-revoked-device-shift`. After local CI, the API branch is pushed with a PR; the web commit stays unpushed. Only local Supabase is used.

Replaced functions: `app.sales_device_from_shift`, `public.move_shift_cash`, `public.close_shift`, `public.post_expense`, `public.reverse_expense`, `public.void_sale`, `app.shift_json`. New private helpers: `app.require_shift_device`, `app.close_shift_internal`. New public RPC: `public.force_close_shift`.

Drawer expenses, expense reversal on an open shift, and sale void/refund also recheck the device. No counter-collection RPC exists on this main. Trusted service-role jobs with no auth.uid() are exempt. Force-close requires cash.adjust, branch access and a reason; its expected/count/difference/ledger logic is shared with normal close. Positive counted cash goes to the branch's existing default safe because the request has no vault field. The shift response includes device_revoked without exposing pairing hashes.
