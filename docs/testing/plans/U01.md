# U01 Suppliers test plan

**Slice:** U01 · Suppliers (EC-53). **Decision:** D53. **Done when:** the statement balance equals invoices − payments − returns.

## SQL (`supabase/tests/u01_suppliers_test.sql`)

```text
npm run db:smoke -- supabase/tests/u01_suppliers_test.sql
```

- **Create:** trims every text field and strips spaces and dashes from the phone; terms default to 0 and optional fields to null. Refused with `VALIDATION_FAILED`: an unknown key or `organization_id`, no or blank name, a name over 150, a bad or short phone, a bad tax number, terms over 365, fractional or as text, a name that isn't a string. A duplicate active name in another letter case → `SUPPLIER_NAME_TAKEN`; the same phone written differently → `SUPPLIER_PHONE_TAKEN`; an archived supplier's name and phone are free again. One `supplier.created` row (no balance in it); refused calls write nothing.
- **Update:** before and after hold only the changed keys; no actual change → no audit row; null and "" clear optional fields; an archived supplier → `SUPPLIER_NOT_FOUND`; another active supplier's name or phone → 409 codes.
- **Done when (statement):** inserted as the superuser (what U02–U04 will write): 2 approved invoices, 1 draft and 1 rejected invoice, 2 payments, a reversal of one, a credit return and a cash return. Closing balance 1050.25 = invoices 1500.50 − payments 400.00 − credit returns 50.25 = `v_supplier_balances.balance` = the supplier's `balance`. Every row in date order with the right running balance; drafts and rejected invoices never listed; the cash return has debit 0 and credit 0; references (supplier invoice no., payment reference, the returned invoice's number), dates and branches are right.
- **Dates:** `from` sets the opening balance (600.00) and the rows and totals cover the period only; `from` and `to`; only `to`; an empty period keeps the balance; `from > to` → `VALIDATION_FAILED`. A supplier with no documents and an archived supplier are readable.
- **List:** active by default, ordered by name, balance on every row; name search any letter case; phone prefix written with spaces, dashes or `+`; `%` and `_` are literal; archived and all; paging; bad limits, status and search length → `VALIDATION_FAILED`.
- **Archive and restore:** refused with a balance (`SUPPLIER_HAS_BALANCE`), with an invoice pending approval and with a sent purchase order (`SUPPLIER_HAS_OPEN_DOCUMENTS`), changing nothing; allowed at 0 (audited as a warning); the same state again writes nothing; restore clashing with an active name or phone → 409 codes; restore audited; an unknown id → `SUPPLIER_NOT_FOUND`.
- **Who:** a WAREHOUSE user (`purchase.invoice_create`) reads the list, a supplier and a statement but gets `PERMISSION_DENIED` on every write; a COLLECTOR and a CASHIER can't read; not an employee → `NOT_AN_EMPLOYEE`; an expired shop reads but can't write (`SUBSCRIPTION_EXPIRED`).
- **Tenancy:** shop B gets `SUPPLIER_NOT_FOUND` for every function on shop A's supplier and sees none of its rows (RLS); shop B may use the same name and phone; no direct table writes; shop A's rows and audit unchanged.
- **Grants:** no anon grants; authenticated runs the six functions, none of the helpers.
- **Guard suites:** `security_guards_test.sql` allowlists the three reads; `tenant_and_permission_test.sql` has a denial case for all six functions. No idempotency key (nothing is posted to a ledger).

## Contracts and API

- `packages/contracts/src/suppliers.test.ts`: the supplier and statement shapes (money as strings, row kinds, refund modes), create trimming and phone normalisation, every refused field, strict bodies and queries (no `organization_id`), update needs a key, list query defaults, `from ≤ to`, the five error codes.
- `src/services/suppliers.service.test.ts`: RPC arguments for every call (search and dates left out when not given), one call per write, malformed rows refused, the five codes mapped without the raw message.
- `src/routes/suppliers.integration.test.ts` (local stack): owner creates → lists (name and phone search) → edits (one audit row, none for no change) → reads an empty statement (and with dates; backwards dates → 400) → archives (gone from the active list, can't be edited) → restores; a duplicate name or phone → 409; a warehouse user reads (200) but can't create, edit or archive (403); a collector gets 403 on the list, a supplier and a statement.
- Cross-shop cases (104 routes): all 7 routes refuse a foreign `x-org-id` (403) and an `organization_id` in the body or query (400); get, statement, edit, archive and restore answer `SUPPLIER_NOT_FOUND` for shop B's supplier and leave it unchanged; no audit row in either shop. Audit drivers for the 4 write routes; permission markers.
