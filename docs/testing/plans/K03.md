# K03 Expenses test plan

**Slice:** K03 · Expenses (EC-61). **Decision:** D61. **Done when:** an expense reduces the vault balance; a shift expense reduces the shift's expected cash.

## SQL (`supabase/tests/k03_expenses_test.sql`)

```text
npm run db:smoke -- supabase/tests/k03_expenses_test.sql
```

- **Categories:** created, renamed, archived and restored with one audit row each; a taken name, an empty name and another shop's category are refused; the same name or state changes nothing and writes no audit row; archived ones are listed only when asked.
- **Done when (vault):** an expense of 150.00 from the safe → the balance drops by exactly 150.00, one `expense` movement of −150.00, an EX number, audited once; the same key → the same expense, nothing spent twice.
- **Done when (shift):** an expense from the caller's open shift → the movement is on the drawer with the shift's id and the shift's expected cash drops by the amount; without an open shift → `SHIFT_REQUIRED`.
- **Refused, nothing changes:** amount 0 or negative, both sources or neither, an archived or unknown category, another branch's safe, a drawer as a vault, an inactive account, another shop's account or receipt file, a file with another purpose, more than the safe or the drawer holds, a `system:` key.
- **Reversal:** not by an accountant (`APPROVAL_OWNER_ONLY`); the owner reverses with a reason → a linked EX row, the money back, the first expense marked reversed, audited as a warning; again → `EXPENSE_ALREADY_REVERSED`; a reversal can't be reversed; the same key → the same reversal, the key of another expense → `IDEMPOTENCY_CONFLICT`. A shift expense after the shift closed needs a vault (`VAULT_INVALID`) and then goes into it.
- **Reads and report:** the list filters by branch, category and day and pages; `include_reversals=false` leaves out both sides; the report totals by category without reversed expenses; a period over a year or reversed dates refused.
- **Who, tenancy, ledger, expired shop, grants:** a cashier can't post or read; an accountant of another branch doesn't see the branch's expenses; shop B gets not found; no direct writes to `expenses`; `app.ledger_mismatches()` is empty; an expired shop reads but can't post; the nine functions are granted, the helpers aren't.
- **Other suites:** `ledger_invariants_test.sql` (replay list: `post_expense`, `reverse_expense`), `tenant_and_permission_test.sql` (denial cases for the nine functions), `security_guards_test.sql` (the four reads allowlisted).

## Contracts and API

- `packages/contracts/src/expenses.test.ts`: the category name and list flag; create (a vault with its branch, or the open shift, never both or neither; amount above 0; strict); reverse; the list and report queries; the report; the error codes.
- `src/services/expenses.service.test.ts`: RPC arguments (the branch and vault, or the shift; note, receipt and reversal vault only when given), the error mapping, list filters and paging, the report.
- `src/routes/expenses.integration.test.ts` (local stack): a cashier gets 403; a taken name is 409; a missing key and a missing source are 400; **two parallel posts with one key → one expense**, the safe at 4 850.00; more than the safe holds → `INSUFFICIENT_FUNDS`; no open shift → `SHIFT_REQUIRED`; a shift expense of 30.00 → expected cash 70.00 of a float of 100.00; an archived category refuses; an accountant can't reverse, the owner does once; the list and the report count only what was spent; after the shift closed the reversal needs a vault; the safe ends at 5 000.00.
- Cross-shop (156 routes): the 10 routes refuse a foreign header and an org id; shop B's category, branch, safe and expense are refused and stay unchanged. Audit drivers for the 6 writes.
