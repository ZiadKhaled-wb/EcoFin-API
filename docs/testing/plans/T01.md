# Test plan T01 — VAT engine (EC-89)

Contracts 0.10.0. Local Supabase only. Decisions in D41 (builds on D31 money rules and D40 settings).

**Done when:** totals match the ETA rounding rules in test cases; a rate change doesn't alter old documents.

## Golden cases (one file, two engines)

`supabase/tests/fixtures/t01_tax_cases.json` holds 13 document cases and 3 return cases. The SQL engine (`app.compute_document_tax`, `app.return_line_tax`) and the TypeScript engine (`computeDocumentTax`, `returnLineTax`) must give exactly these results. The SQL test embeds the same JSON, and a vitest check fails if the two copies differ.

| Case | What it proves |
|---|---|
| G01–G03 | Prices without VAT (tax = round(net × rate)) and with VAT (net = round(gross / 1.14), tax = gross − net) |
| G04, G05 | Half-up at .005 (0.035 → 0.04); net rounding on a VAT-inclusive price |
| G06 | Quantity × unit price before tax |
| G07 | Tax is rounded per line, never on the total (0.04 + 0.04, not 0.07) |
| G08 | Standard, zero-rated and exempt lines on one document |
| G09 | A line discount comes off before tax |
| G10–G12 | A document discount is spread by amount (largest remainder, leftover piasters to the earlier line), then each line is taxed |
| G13 | Large values stay exact |
| R01–R03 | Returns reverse the original line's tax: proportional, half-up, and the last return takes the remainder so every return adds back exactly |

The rounding follows D31 and **must be confirmed by the client's accountant** against ETA's rules. ETA receipts (T02) carry up to 5 decimals; our documents store 2.
