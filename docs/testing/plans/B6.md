# Test plan B6 (F04 server: auth and sessions)

Run from the repo root in Git Bash on the Sprint 1 dev machine. Prefix every npm/npx command with `export NODE_OPTIONS=--no-network-family-autoselection;`. Local Supabase only (`npm run db:start` / `db:reset`); nothing is linked or pushed.

- **Unit** (`npm test`): Supabase and the service-role module are mocked. 90 F04 cases across `src/services/auth.service.test.ts`, `src/services/auth.admin.test.ts`, `src/middleware/auth.test.ts`, `src/utils/supabase.test.ts` and `src/routes/auth.test.ts`.

- **Integration** (`src/routes/auth.integration.test.ts`, 11 cases, skipped unless `RUN_INTEGRATION=1`): the real app runs in-process with supertest against local GoTrue, Postgres and Mailpit, so the "server can't start" problem doesn't block it. Command:
  ```bash
  S=$(npx -y supabase@2.119.0 status -o json)
  RUN_INTEGRATION=1 SUPABASE_URL=http://127.0.0.1:54321 \
  SUPABASE_ANON_KEY=$(echo "$S" | node -pe 'JSON.parse(require("fs").readFileSync(0)).ANON_KEY') \
  SUPABASE_SERVICE_ROLE_KEY=$(echo "$S" | node -pe 'JSON.parse(require("fs").readFileSync(0)).SERVICE_ROLE_KEY') \
  FRONTEND_URL=http://localhost:5173 npx vitest run src/routes/auth.integration.test.ts
  ```
  Observed on 3 Oct 2026 after `npm run db:reset`: all 11 passed (the reset case in one run, the other 10 in a later run). Local GoTrue sends at most **2 emails per hour** (`[auth.rate_limit] email_sent = 2`), so the reset case fails if more than 2 recovery emails were sent in the last hour. The suite puts the seed passwords back when it finishes.
