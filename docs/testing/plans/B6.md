## Service-role writes (for D14 / D25)

`src/services/auth.admin.ts` is the only module that uses the service role for auth. Its writes:
- `login_attempts` inserts for every login attempt, **and for every current-password check on change-password** (success and failure), so wrong current passwords count toward the D17 lockout of that email (identifier = the login email, `tenant_slug` NULL). Tests: B6-12, B6-32 and auth.service.test.ts "locked out -> 429 without checking the password".
- `auth_clear_must_change_password(<verified auth user id>)`, only after Supabase Auth accepted the new password (D24). Tests: B6-21b, B6-21c.
