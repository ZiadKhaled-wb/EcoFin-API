# C02 Products test plan

**Slice:** C02 · Products (EC-43). **Decision:** D44.

## SQL (`supabase/tests/c02_products_test.sql`)

```text
npm run db:smoke -- supabase/tests/c02_products_test.sql
```

- **Create:** generated barcode is 13 digits, starts with 2 and has a valid check digit (null and empty barcode); `app.ean13_check_digit` on known codes; SKU trimmed, upper-cased and unique in any case (`PRODUCT_SKU_TAKEN`); barcode unique (`PRODUCT_BARCODE_TAKEN`); the shop default tax class when omitted; archived, null or another shop's tax class → `TAX_CLASS_NOT_FOUND`; archived category → `PRODUCT_CATEGORY_ARCHIVED`, another shop's → `CATEGORY_NOT_FOUND`; another shop's image or a non-product file → `FILE_NOT_FOUND`; ETA pair rule; `avg_cost`, `is_active`, `organization_id` in the body → `VALIDATION_FAILED`; bad money, integers, SKU and barcode shapes.
- **Price changes:** a branch manager with a `catalog.price_change` override of `granted=false` can rename but gets `PERMISSION_DENIED` changing a price; the same price in another spelling is no change; the owner's price change writes one `product.price_changed` row with before/after of every changed key; a non-price edit writes `product.updated`; no change writes nothing.
- **Barcode on update:** null or empty generates a new valid code; a typed code can be set back.
- **Serialized lock:** after a `units` row (and, for another product, a `stock_movements` row) changing `is_serialized` → `PRODUCT_SERIAL_LOCKED`; other edits still work.
- **Archive / restore:** `archived_at` and `is_active` move together; same-state calls write nothing; archived products are not in `lookup_product` (barcode or SKU), are in `get_product` and in `list_products(status 'archived')`; an archived product can't be edited; restore refused under an archived category and with an archived tax class.
- **Old sales (the slice's Done when):** a sale line inserted for a product still joins to its name and SKU after the product is archived.
- **Lookup:** exact barcode (trimmed), then SKU in any case, barcode wins over SKU; unknown or another shop's code → `PRODUCT_NOT_FOUND`.
- **List:** Arabic name, English name, SKU prefix, exact barcode (a partial barcode does not match), LIKE wildcards literal; category filter with and without subcategories (C01 helper); paging with the full total, name order; bad status and page size refused.
- **Tenancy and roles:** another shop's ids → `PRODUCT_NOT_FOUND`, shop B unchanged (rows and audit); a cashier lists, gets and looks up but gets `PERMISSION_DENIED` on every write; a non-employee gets `NOT_AN_EMPLOYEE`.
- **Audit and grants:** one row per write; archive is `warning`, restore `info`; no anon grants; `app.*` helpers not granted; authenticated executes exactly the six public functions.

The guard suites register the three writes (`tenant_and_permission_test.sql`, `catalog.manage`) and the three reads (`security_guards_test.sql` allowlist, with reasons).

## Contracts (`packages/contracts/src/products.test.ts`)

SKU pattern and upper-casing; required create fields; strict bodies reject `avg_cost`, `organization_id`, `is_active`, `archived_at`; money strings only (no negatives, at most 2 decimals); empty/null barcode → null (generate); ETA pair rule (update: only when both keys are sent); integer ranges; the list query defaults (`active`, subcategories on, page 1 / 50) and flags; the lookup code; the five error codes.
