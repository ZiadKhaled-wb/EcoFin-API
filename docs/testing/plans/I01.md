# I01 Stock view test plan

**Slice:** I01 · Stock view (EC-47). **Decision:** D47. **Done when:** the numbers equal the ledger sums for every product and branch.

## SQL (`supabase/tests/i01_stock_view_test.sql`)

```text
npm run db:smoke -- supabase/tests/i01_stock_view_test.sql
```

- **Numbers:**
  - Setup: purchases and sales, a damaged return, a **sent** transfer (in transit to the destination; the stock already left the source), a received transfer (not in transit), and an active plus a released reservation.
  - Checks: on hand, reserved, available, damaged and in transit per product and branch.
- **Done when:** for every row of the view, `on_hand` / `damaged` = the sum of `stock_movements` per stock state, `reserved` = the active reservations, `in_transit` = the sent transfer lines, `available = on_hand − reserved`; and `app.ledger_mismatches()` is empty.
- **Rows:** every active product in every branch (zeros included). Archived products show only while they hold stock. Order: name, then the main branch.
- **Low stock:** the product's own min, else the shop's (3); `low = available < min_level`; the `low_only` filter.
- **Filters:** branch, category with and without subcategories (C01 helper), search (name, SKU prefix, exact barcode), paging with the full total.
- **Scope and access:**
  - A cashier sees only the branches they work in; another branch → `BRANCH_DENIED`; another shop's branch → `BRANCH_NOT_FOUND`.
  - No `stock.view` → `PERMISSION_DENIED`; a non-employee → `NOT_AN_EMPLOYEE`.
  - An expired shop can still read.
- **Drill-down:** newest first, running balance per branch and stock state (the newest equals the view's on hand); type and source document on each movement; all branches in scope when no branch is given; paging; another shop's product or branch refused.
- **Read only:** no audit rows; no anon grants. The guard suites register both reads (`security_guards_test.sql` allowlist, `tenant_and_permission_test.sql` denial cases with `stock.view`).

## Contracts and API

- `packages/contracts/src/stock.test.ts`: integer quantities, query defaults and flags, strict queries, the movement types.
- `src/services/stock.service.test.ts`: paging → limit/offset, only the given filters, malformed rows refused, error codes.
- `src/routes/stock.integration.test.ts` (local stack): a product's ledger movements show as on hand / available / low through `GET /api/stock` (equal to the ledger sum), the low filter, the drill-down with running balances; a collector gets 403.
- Cross-shop cases for `GET /api/stock` and `GET /api/stock/movements` (route count 71).
