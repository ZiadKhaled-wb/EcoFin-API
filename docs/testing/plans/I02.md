# I02 Stock adjustments and counts test plan

**Slice:** I02 · Stock adjustments and counts (EC-48). **Decision:** D48. **Done when:** a posted count makes the stock equal the counted numbers and leaves ledger entries with the reason.

## SQL (`supabase/tests/i02_stock_adjustments_test.sql`)

```text
npm run db:smoke -- supabase/tests/i02_stock_adjustments_test.sql
```

- **Adjustments:**
  - found +12: stock and ledger 12, number `<branch>-SA-yy-000001`, reason and note kept; the ledger row is type `adjustment` and points at the adjustment line; cost = the product's average cost (a unit: the unit's cost).
  - The same idempotency key again returns the same document and posts nothing.
  - damage / loss can't add, found can't remove (`ADJUSTMENT_SIGN_INVALID`); `other` needs a note; `count` can't be picked; zero, duplicate, malformed lines, an unknown key in a line, no lines, a short key → `VALIDATION_FAILED`.
  - More than on hand → `OUT_OF_STOCK`, and nothing is posted or numbered.
  - Serials: unit required (`UNIT_REQUIRED`), not allowed on a plain product (`UNIT_NOT_ALLOWED`), ±1 only; a unit of another branch can't leave (`UNIT_NOT_AVAILABLE`); a loss writes the unit off, found brings it back; a sold unit can't be found again (`UNIT_NOT_AVAILABLE`), nor counted back in a count.
  - Another shop's product or branch refused; one audit row per adjustment with its lines; list (reason filter, paging) and get.
  - The I01 drill-down shows the adjustment number and reason on its movements.
  - A cashier (no `stock.adjust`) is refused; an employee with it can't adjust a branch they don't work in.
- **Counts:**
  - A whole-branch count: number `SC`, a line per product and per unit in the branch; the same key returns the same count; a second open count over the same products → `STOCK_COUNT_OPEN`; another branch → `BRANCH_DENIED`.
  - The sheet's expected quantities, typed counts, scans (barcode +1 each, SKU, serial = 1), a serialized barcode (`UNIT_REQUIRED`), a serial in another branch (`UNIT_ALREADY_IN_STOCK`), unknown codes, other shop's product, bad quantities.
  - Filters (uncounted, different, search by serial).
  - Posting with uncounted lines → `STOCK_COUNT_INCOMPLETE`; a sale while counting: expected follows the live stock.
  - **Done when:** after posting (uncounted as zero) the stock in `stock_levels` and in the ledger equals the counted numbers (a missing serial written off); the movements are one `count` adjustment linked to the count; the sheet stores the expected quantities at posting; `app.ledger_mismatches` is empty.
  - Posting again answers the same; a posted count can't change or be cancelled; the post key reused for another count → `IDEMPOTENCY_CONFLICT`.
  - Category counts: scope with subcategories, out-of-scope product refused, overlapping category refused, other categories at the same time; a found serial is added to the sheet; cancel (twice), a cancelled count can't be posted; no differences → posted without an adjustment.
  - Audit rows (created, posted, cancelled); shop B can't read or touch shop A's counts or adjustments; an expired shop reads but can't write.
- **Grants:** no anon grants; helpers aren't callable by `authenticated`.
- **Guard suites:** `security_guards_test.sql` allowlists the four reads (they use `app.has_permission`); `tenant_and_permission_test.sql` has a denial case for all ten functions.

## Contracts and API

- `src/services/stock.service.test.ts`: RPC arguments (nulls, idempotency key, paging of count lines), error codes.
- `src/routes/stock.integration.test.ts` (local stack): adjustment without a key (400), idempotent repeat, wrong direction (400), out of stock (409); a count scanned, typed and posted; the stock equals the counted number and the drill-down shows `count` and `found` with their numbers.
- Cross-shop cases for the ten routes (route count 81); audit drivers for the four audited writes; permission markers.
