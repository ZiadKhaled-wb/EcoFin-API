# O03 POS devices test plan

**Slice:** O03 · POS devices (EC-146). **Decision:** D68. Contracts **0.38.0**, migration `20261013090000_o03_pos_devices.sql`.
**Done when:** (1) a paired POS computer opens a shift and makes a sale whose `device_id` is set and whose ETA receipt is prepared (not `BLOCKED:NO_DEVICE`); (2) a revoked device's next request is rejected; (3) creating one device over the plan limit fails.

| Done when | Proven by | Status |
| --- | --- | --- |
| (1) paired computer, shift, sale with its device, receipt prepared | O03-I-003 and O03-I-004 (the shift is opened on the device of the request; the sale and its fiscal row carry it; the fake ETA accepts the receipt), O03-S (the `sales` trigger, the T02 fiscal row), the Web e2e `e2e/pos-device.spec.ts` | passing (local) |
| (2) a revoked device's next request is rejected | O03-I-006 (unpaired, re-paired and turned off: 403 `DEVICE_REVOKED` on the next request), O03-U (`deviceContext`), O03-S (`resolve_device`) | passing (local) |
| (3) one device over the plan limit fails | O03-I-001 (`PLAN_LIMIT_REACHED` on the third device of a `starter` shop), O03-S (`starter`: 2 devices; turning a device on again also counts) | passing (local) |

One row per test: 50 unit, 7 contracts, 110 SQL statements (114 checks: one statement makes five), 9 integration, plus 6 audit drivers and 7 cross-shop cases in the shared suites. Web: `EcoFin-Web/docs/testing/plans/O03-web.md`.

Two rules were added after the security review of the first commit (the database can be called without the API, with a user's own JWT): a device id counts in the database only with the hash of its token (`x-device-token-hash`), and `pair_device` counts failed attempts itself and answers NULL. O03-I-008 proves both against PostgREST directly; O03-S has the cases named "current device: a hand-made x-device-id ..." and "limit: ...".
