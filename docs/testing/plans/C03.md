# C03 Barcode labels test plan

**Slice:** C03 · Barcode labels (EC-44). **Decision:** D45. **Done when:** a printed label scans correctly in the POS.

## SQL (`supabase/tests/c03_labels_test.sql`)

```text
npm run db:smoke -- supabase/tests/c03_labels_test.sql
```

- `list_product_units`: the owner sees in-stock units of every branch in serial order (default status); each unit has id, serial, branch and status; `sold` and `all` filters; a product without units answers `[]`; an unknown status → `VALIDATION_FAILED`; another shop's or a missing product → `PRODUCT_NOT_FOUND`.
- A cashier assigned to one branch sees only that branch's units; a non-employee gets `NOT_AN_EMPLOYEE`; shop B sees only its own unit.
- Read only (no audit rows); no anon grant; authenticated may execute. Registered in `security_guards_test.sql` (allowlist) and `tenant_and_permission_test.sql` (excluded reads).

## Contracts and API

- `products.test.ts`: `ProductUnitsQuery` defaults to `in_stock`, accepts `all`, rejects unknown statuses and keys; `ProductUnitList` parses units.
- `products.service.test.ts`: rpc arguments and parsing for `listProductUnits`.
- `products.integration.test.ts` (local stack): a cashier lists a serialized product's units in serial order; `status=sold` is empty; `status=lost` is 400.
- Cross-shop case for `GET /api/products/:id/units` (another shop's product → 404, a foreign `x-org-id` → 403); route count 69.

## Web (EcoFin-Web)

- `src/lib/barcode.test.ts`: EAN-13 and Code 128 encodings against known patterns (check digits, start/stop, Code 128 checksum, subset C for digit runs).
- `LabelsPage.test.tsx`: products and units are added with quantities, the template changes the sheet, a serialized product offers its units, printing calls `window.print`, in Arabic and English.
- **Done when (scan):** the label sheet is rendered in a real browser (Playwright), the barcode image is decoded with ZXing, and the decoded text is looked up through `GET /api/products/lookup` → the same product.
