# I03 Branch transfers test plan

**Slice:** I03 · Branch transfers (EC-49). **Decision:** D49. **Done when:** stock is never counted in both branches or in neither; in-transit stock shows in I01.

## SQL (`supabase/tests/i03_transfers_test.sql`)

```text
npm run db:smoke -- supabase/tests/i03_transfers_test.sql
```

- **Draft:** branch names on the transfer; destinations = every active branch (not only the sender's); `TR` number in the source branch, notes trimmed, nothing moves; the same key returns the same draft; same branch (`TRANSFER_SAME_BRANCH`), another shop's branch or product (`BRANCH_NOT_FOUND`, `PRODUCT_NOT_FOUND`), a source branch the sender doesn't work in (`BRANCH_DENIED`), a serial missing or not in the source (`UNIT_REQUIRED`, `UNIT_NOT_AVAILABLE`), quantity 0; lines replaced while draft.
- **Send:** the stock leaves the source, shows in transit at the destination (`v_stock_in_transit` and the I01 list), the unit is `in_transit`; **Done when:** on hand in every branch + in transit + written off = what there was, for every product; sending again moves nothing; a sent transfer can't be edited or cancelled (`TRANSFER_ALREADY_SENT`); the sender can't receive in a branch they don't work in.
- **Receive:** received more than sent, an unknown line, a shortage without a reason → `VALIDATION_FAILED`; with 1 lost: `partially_received`, the destination holds the rest, nothing in transit, the unit in stock there, one `loss` adjustment at the destination with the transfer number in its note and a reserved `system:` key; receiving again moves nothing; **Done when** holds again; the ledger rows point at the transfer with the average cost.
- **More:** a serial that arrived broken is written off (`damage`); sending more than on hand → `OUT_OF_STOCK` and the draft stays; a draft can't be received (`TRANSFER_NOT_SENT`); cancel (twice); a cancelled transfer can't be sent (`DOCUMENT_FINAL`).
- **Security review:** a unit reserved after the draft was saved can't be sent (`UNIT_NOT_AVAILABLE`) and stays reserved in the source; a reserved unit can't be written off by an adjustment; a client key starting with `system:` is refused.
- **Scope and access:** lists (status, either side, paging); the receiver sees the transfers coming in and can't send from the source; a cashier can't create or receive but reads; shop B can't read, send or receive shop A's transfers; audit rows; ledger caches match; an expired shop reads but can't write; grants.
- **Guard suites:** `security_guards_test.sql` allowlists the two reads; `tenant_and_permission_test.sql` has a denial case for all eight functions (a third branch of shop one as the destination); `ledger_invariants_test.sql` lists the create replay.

## Contracts and API

- `packages/contracts/src/stock.test.ts`: draft and update bodies (different branches, positive quantities, no duplicates, strict), the receipt body (only shortages, loss or damage), the transfer shape.
- `src/services/stock.service.test.ts`: RPC arguments (null notes and units, the key), send / cancel / receive, error codes.
- `src/routes/stock.integration.test.ts` (local stack): found 6 -> transfer 6 to a new branch -> sent (main 0, second 0 on hand, 6 in transit) -> received with 1 lost (second 5, nothing in transit, one `loss` adjustment) -> cancel refused.
- Cross-shop cases for the eight routes (route count 89; destinations never list another shop's branches); audit drivers for the five writes (BR1 -> BR2 of shop one); permission markers.
