# N01 Installment rules engine test plan

**Slice:** N01 · Installment rules engine (EC-80). **Decision:** D76. **Rules:** `docs/ISLAMIC_FINANCE_RULES.md`. **Done when:** schedule lines always sum to the total payable; changing the policy changes new contracts only; the server rejects terms that break the policy.

## SQL (`supabase/tests/n01_installment_terms_test.sql`)

```text
npm run db:smoke -- supabase/tests/n01_installment_terms_test.sql
```

Shops a and b (retail) and c (starter); in shop a an owner, a cashier and a warehouse user; customers with a limit, without one, blocked; shop B's customer. Policies are inserted as the database owner (a newer version where a case needs one). Contracts and schedule lines are written directly (nothing writes them yet: N02), then the two commit-time triggers are run with `SET CONSTRAINTS ... IMMEDIATE`.

- **Golden cases:** the 35 cases of `fixtures/n01_terms_cases.json` (embedded copy) give exactly the expected terms in SQL; at least 30 cases.
- **Always adds up (Done when):** a generated sweep (3 rounding steps × 5 prices × 3 down payments × monthly 1-60, weekly 1-104, daily 1-180; about 900 schedules): Σ amount = total payable, Σ principal = financed, Σ profit = markup, every line > 0 with principal + profit = amount, seq 1..n, dates rising.
- **Examples:** 1000 / 3 at step 0.01 → 333.34, 333.34, 333.32; step 1 → 334, 334, 332; financed 12 000, 12 months at 20 % → 2400.00 profit, 12 × 1200.00; 31 Jan → 28 Feb → 31 Mar → 30 Apr; 29 Feb in 2028; weekly × 10 = 3 months, daily × 45 = 2; the answer has the whole-term profit % and no per-period rate.
- **Rules (Done when):** one piaster below the 10 % minimum down payment, at it; 25 months over 24; a first due date of today; the default first due date (one period).
- **Confirm side:** no policy → `POLICY_NOT_SET`; an old version → `POLICY_CHANGED` with the current version; a broken rule → `INSTALLMENT_TERMS_INVALID` with the violations; valid terms come back with their lines; a malformed amount, 521 installments → `VALIDATION_FAILED`.
- **Triggers (any writer):** the engine's contract and lines commit; a piaster moved inside a line, a piaster more, a gap, due dates a day off, no lines, a lower profit, no down payment → refused; a migrated contract keeps terms outside the policy but its lines must add up and run without a gap (`SCHEDULE_NOT_BALANCED`).
- **Policy change (Done when):** after a new version the earlier contract and its lines are unchanged; a new contract on the old version → `POLICY_CHANGED`; on the new version it commits with the new profit.
- **Preview:** a cashier without a customer (terms, `can_confirm` false); with a good customer (credit, guarantors, survey; `can_confirm` true); above 20 000 a guarantor is needed (`selected_met` false until the linked one is picked; an unlinked one is not counted and fails R04); above 30 000 a survey is needed; a customer over the limit; a violation is answered, not raised; a blocked customer → `CUSTOMER_BLOCKED`; shop B's customer → `CUSTOMER_NOT_FOUND`; an unknown key or a repeated guarantor → `VALIDATION_FAILED`; nothing written (audit rows and contracts unchanged).
- **Who:** a warehouse user → `PERMISSION_DENIED`; not an employee → `NOT_AN_EMPLOYEE`; a starter shop → `MODULE_NOT_IN_PLAN`; installments off → `INSTALLMENTS_DISABLED`; an expired shop may preview.
- **Grants:** no `app` helper of N01 is executable by `authenticated`; the preview is granted to `authenticated` only; both triggers are deferred constraint triggers.
- **Other suites:** `tenant_and_permission_test.sql` (the preview's denial case: a role without `installment.create` is refused, the owner's same call works), `security_guards_test.sql` (the preview allowlisted as a read).

## Contracts and API

```text
npm run test:contracts
npx vitest run src/test/n01-golden.test.ts
npm run check:cross-shop && npm run check:audit && npm run check:permissions
```

- `packages/contracts/src/installments.test.ts`: every golden case (and its answer parses as `InstallmentTerms`), the 12-month example, sums over steps × counts × prices, rounding and the `rounding` violation, a down payment at the cash price, the percent minimum half-up, the smallest down payment for one installment and per day of the month, month limits and amount tiers, the minimum installment, the first due date range, a frequency not allowed, month-end and leap-year dates, durations, the preview body schema (an injected organization id, a repeated guarantor, 521 installments, a zero price and a negative down payment are refused).
- `src/test/n01-golden.test.ts`: the SQL test's embedded copy equals the fixture file.
- Cross-shop (`POST /api/installments/preview`): a foreign shop header → 403; an injected `organization_id` → 400; shop B's customer → 404 `CUSTOMER_NOT_FOUND`; shop B's guarantor picked for a shop A customer is not counted (`selected` 0); no audit row in either shop.
- Audit registry: the route is `none` (read only).
