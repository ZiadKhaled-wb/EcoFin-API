# R01 Customers test plan

**Slice:** R01 · Customers (EC-63). **Decision:** D63. **Done when:** a user without the PII permission sees masked IDs; duplicate national IDs are rejected.

## SQL (`supabase/tests/r01_customers_test.sql`)

```text
npm run db:smoke -- supabase/tests/r01_customers_test.sql
```

- **Parser and helpers:** the birth date, gender and governorate of valid IDs (century 2 and 3, a leap day, born outside Egypt); refused: other centuries, month 13 / 00, day 00, 30 February, 29 February of a common year, an unknown governorate, 13 or 15 digits, letters, null. The mask; phones in every usual spelling; Arabic-Indic and Persian digits.
- **Create:** trims, joins spaces, normalises phones and the ID; birth date and gender from the ID; defaults; typed birth date without an ID; a business customer. Refused with nothing written: unknown keys (`credit_limit`, `status`, `organization_id`), no name or phones, 0 or 6 phones, a repeated or bad phone, a bad name, every kind of bad ID, a birth date or gender that contradicts the ID, bad dates, income and tax number.
- **Done when (duplicates):** the same national ID written with dashes → `CUSTOMER_NATIONAL_ID_TAKEN`, the details name the customer who has it; the same phone on another customer is allowed; the ID never appears in `audit_log`, only its mask.
- **Update:** changed keys only in the audit; no change, no row; a new ID replaces the birth date and gender and is a `warning` with the two masks; filling an empty ID is `info`; another customer's ID refused; removing the ID keeps the birth date.
- **Status:** blocking needs a reason; `watch` can't be set by hand but shows, filters and can be cleared; one `customer.status_set` row per real change with the reason.
- **Search and list:** order, paging, name (letter case, Arabic letter forms), phone (part, full, Arabic digits), the whole ID, an ID prefix with `customer.view_pii`, literal wildcards, the status filter, bad arguments.
- **Done when (masking):** a cashier (`customer.create` only) creates with an ID and gets it back masked, reads and lists masked (no 14-digit number anywhere in the list), finds a customer by the whole ID but not by a prefix, can't select `national_id` from the table. An editor without `customer.view_pii` edits other fields but can't replace, remove or re-send an existing ID, and may fill an empty one. A manager sees and replaces IDs.
- **Who, plan, expired shop, tenancy, grants:** a collector reads masked and can't write; a warehouse user can't read; not an employee; a Starter shop → `MODULE_NOT_IN_PLAN` on all five; an expired shop reads but can't write; shop B gets not found, sees nothing even by the whole ID, and may register the same ID; the five functions are granted, the helpers and the `national_id` column aren't.
- **Other suites:** `tenant_and_permission_test.sql` (denial cases for the five functions), `security_guards_test.sql` (the two reads allowlisted).

## Contracts and API

- `packages/contracts/src/nationalId.test.ts`: the same parser vectors as the SQL test; "not after today"; the check digit is not verified; digit and mask helpers.
- `packages/contracts/src/customers.test.ts`: phone normalisation; create (trimming, required fields, phones, IDs, income, dates, business rule, strictness); update; status (a reason to block, no `watch`); the customer, list, query and error-detail shapes.
- `src/services/customers.service.test.ts`: RPC arguments, paging, the reason only when given, the duplicate-ID details passed on (and a malformed detail dropped), the error mapping.
- `src/routes/customers.integration.test.ts` (local stack): the owner creates with an ID, finds the customer by name, phone, whole ID and prefix, edits, blocks and unblocks (audit rows checked, no ID in them); a duplicate ID is 409 with details and a bad ID 400; **a cashier only ever receives masked IDs** and can't edit or block; ID photos are counted for everyone and listed only with `customer.view_pii`; a collector reads masked, a warehouse user gets 403; a Starter shop gets `MODULE_NOT_IN_PLAN`.
- Cross-shop (164 routes): the 5 routes refuse a foreign header and an org id; shop B's customer is not found, not listed (by name or by national ID) and stays unchanged; shop B's national ID is free in shop A. Audit drivers for the 3 writes.
