# I05 Movement history test plan

**Slice:** I05 · Movement history (EC-51). **Decision:** D51. **Done when:** every movement links to the document that caused it.

## SQL (`supabase/tests/i05_movement_history_test.sql`)

```text
npm run db:smoke -- supabase/tests/i05_movement_history_test.sql
```

- **Done when:** every movement of a shop with real documents (a serial registration, a transfer sent and received, two adjustments) names a source document that exists in the shop; transfers carry their number and "from → to", adjustments their number and reason; each row names the product, branch and employee.
- **Running balance:** per product, branch and stock state, newest first; the newest balance equals the stock level; a type filter (sales only) and a date filter keep the real balance (8, not -2).
- **Filters:** no product = the whole shop; branch; serial in any case (only that unit, registered -> sent -> received); an unknown serial or a serial of another product finds nothing; an empty type list = every type; paging keeps the total; the I01 positional calls still work.
- **Refusals:** dates the wrong way round, a serial over 64 characters or blank, a page over 100 (`VALIDATION_FAILED`); another shop's product (`PRODUCT_NOT_FOUND`) or branch (`BRANCH_NOT_FOUND`); a cashier's other branch (`BRANCH_DENIED`); no stock.view, export.data without stock.view, a cashier without export.data (`PERMISSION_DENIED`); not an employee.
- **Branch scope:** a cashier of main sees only main's rows, and only main's steps of a serial that went to second.
- **Export:** the accountant's export equals the history's rows; 10 001 rows → `EXPORT_TOO_LARGE` with `{"total":10001,"limit":10000}` and no audit row, while the history still pages through them; exactly one `stock_movements.exported` audit row with the employee, the filters and the row count; reads write no audit rows.
- **Expired shop:** the history and the export still work.
- **Ledger and grants:** ledger caches match; no anon grants; authenticated may run the two public functions, not the helpers.
- **Guard suites:** `tenant_and_permission_test.sql` has a denial case for `export_stock_movements` (a role without export.data); `security_guards_test.sql` keeps `list_stock_movements` allowlisted (read with app.has_permission); the export calls `app.require_permission`. No idempotency key, so nothing in `ledger_invariants_test.sql`. The I01 grant check names the new signature.

## Contracts and API

- `packages/contracts/src/stock.test.ts`: every filter optional, serial trimmed and upper-cased, types as a comma list (unknown type refused), dates in order and real, the export body (no paging, types as an array), the export limit and `ExportTooLargeDetail`.
- `src/services/stock.service.test.ts`: only the given filters are passed; an empty type list is left out; the export's RPC arguments; `EXPORT_TOO_LARGE` keeps valid details only.
- `src/routes/stock.integration.test.ts` (local stack): two adjustments through the API show up under `types=adjustment` with their numbers and reasons; a sales filter hides them; bad types and reversed dates → 400; the export equals the history and writes one audit row; a collector's export → 403 naming export.data; `GET /api/stock/movements` with no product is now 200.
- Cross-shop cases (94 routes): the history refuses shop B's branch; the export refuses shop B's product and branch, a foreign shop header (no audit row there) and an `organization_id` in the body. Audit driver for `POST /api/stock/movements/export`; permission markers.
