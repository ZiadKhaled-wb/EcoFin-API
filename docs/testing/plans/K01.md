# K01 Vaults test plan

**Slice:** K01 · Vaults (EC-59). **Decision:** D56. **Done when:** a transfer changes both balances once; the ledger view adds up to the balance.

## SQL (`supabase/tests/k01_vaults_test.sql`)

```text
npm run db:smoke -- supabase/tests/k01_vaults_test.sql
```

- **Create / rename:** a safe in a branch (trimmed, balance 0, not the default); a shop-wide bank; a safe without a branch, a drawer, a wallet, a blank or 101-character name → `VALIDATION_FAILED`; the same name in the same branch or among shop-wide banks → `CASH_ACCOUNT_NAME_TAKEN`, in another branch allowed; another shop's branch → `BRANCH_NOT_FOUND`; rename audited once, the same name again writes nothing; a drawer can't be renamed (not found). The list shows safes and banks only, active by default, shop-wide last, the default safes marked; branch and kind filters.
- **Opening:** 5 000.00 on the empty main safe → one `opening` movement from one completed `opening_cash` import job, audited; the same key changes nothing; the key for another account, a second opening (`CASH_ACCOUNT_HAS_MOVEMENTS`), 0, 3 decimals, a short note, a `system:` key, a drawer, an inactive account are refused; a shop-wide bank books in the caller's branch.
- **Done when (transfer):** 1 200.00 from the safe to a bank → −1 200.00 / +1 200.00, two movements, one CX transfer, audited once; the same key → the same transfer; more than the safe holds → `INSUFFICIENT_FUNDS`, nothing posted; from = to, a drawer side, 0, 3 decimals, a `system:` key, an inactive side refused; a shop-wide bank books in the other side's branch.
- **Done when (ledger):** with no dates closing = `cash_balances` = the sum, newest first, every running balance right; with `from` the opening is the sum before it; with `to` the closing is the sum up to it; paging keeps the running balance; from after to refused. Transfers list by account, newest first.
- **Deactivate / reactivate:** with a balance → `CASH_ACCOUNT_HAS_BALANCE`; an empty default vault → `CASH_ACCOUNT_IS_DEFAULT`; allowed at 0 (inactive, still readable, audited once; again: no audit); reactivate audited; an inactive account's name stays taken.
- **Who:** an ACCOUNTANT reads its branch and shop-wide banks and transfers, but can't create or post an opening and doesn't see another branch's safe; a manager of the second branch can't move money out of main's safe (`BRANCH_DENIED`), sees its safes and the shop-wide bank, moves money from its safe into main's, can't read main's ledger; a CASHIER gets `PERMISSION_DENIED`; a non-employee `NOT_AN_EMPLOYEE`.
- **Tenancy, expired shop, closed day, grants:** shop B gets not found for a's accounts, ledgers, transfers (also as either transfer side) and a's branch; no direct writes to `cash_accounts` or `cash_movements`; ledger caches match; an expired shop reads but can't transfer or create (`SUBSCRIPTION_EXPIRED`); a closed day refuses a transfer out of or into that branch; the ten functions are granted, the helpers aren't.
- **Other suites:** `ledger_invariants_test.sql` (replay list: `create_cash_transfer`, `post_cash_opening`), `tenant_and_permission_test.sql` (denial cases for the ten functions), `security_guards_test.sql` (the five reads allowlisted).

## Contracts and API

- `packages/contracts/src/cash.test.ts`: accounts and the list, the list query (active by default, strict), create (a safe needs a branch), opening and transfer bodies (amount above 0, two decimals, two different accounts), date order, the ledger, the error codes.
- `src/services/cash.service.test.ts`: RPC arguments (filters, paging, a shop-wide bank sends no branch, an empty note sent as `''`), malformed rows refused, error codes mapped.
- `src/routes/cash.integration.test.ts` (local stack): the owner creates a bank (a duplicate is 409), opens the main safe, transfers (the same key → the same transfer; too much → `INSUFFICIENT_FUNDS`), reads both ledgers (closing = balance), can't deactivate the funded bank, moves the money back and deactivates it; an accountant transfers (201) but can't create (403); a cashier gets 403.
- Cross-shop (122 routes): the 11 routes refuse a foreign header and an org id; shop B's accounts and transfers are not found, also as either transfer side, and no money moves. Audit drivers for the 6 writes.
